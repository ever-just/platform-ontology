SKAdNetwork 4 (postbacks)

Apple sends the ad network a signed, delayed, anonymized report that an ad led to an install.

Used to track youAds and install trackingApple attributionAndroid and iPhoneBefore you installWhen the app opens

In one line

Can tell an ad network an ad led to an install, in a delayed report

Apple sends the ad network a signed, delayed, anonymized report that an ad led to an install.

Gives ad networks proof an ad drove an install without a device ID. Reports are coarse, delayed and may be dropped for small campaigns.

What it can and can't do

Reach 2 of 4A delayed, anonymous count

What the user does: You tap an ad, install the app, then use it for a few days

It can

  • Send a signed report that an ad led to an install
  • Send up to three reports over weeks
  • Show a small campaign number (2 to 4 digits)

It cannot

  • Give your name or device ID
  • Report the same day; delays and low counts remove detail
  • Work on Android; it uses the install referrer

How it differs between platforms: iPhone only (iOS 11.3 and later; iOS 16.1 for the newest version). Android uses the install referrer.

Technical limits

  • Postbacks to the ad network only (app developer does not get it directly)
  • Randomized delay per window
  • Crowd anonymity tiers cut data on small campaigns
  • No user or device identifiers

The story

What it is

Apple's system that tells an ad network an ad led to an install, in a delayed, anonymous report.

For you

You tap an ad, install and open the app. Days later Apple sends the ad network a signed note that one install came from that ad, with no name or device ID.

For makers

It gives ad networks proof an ad drove an install, without an ID. Reports are coarse and delayed and may be dropped for small campaigns, so makers choose their budgets with less detail than before.

Risks

  • Coarse and delayed
  • Small campaigns lose detail

Android and iPhone in short

  • Android: Android has no SKAN. Google used the install referrer and advertising ID.
  • iPhone: SKAdNetwork 4 added three postback windows and coarse values.

What the platform says

  • Apple: SKAdNetwork. A privacy preserving way to measure ad driven installs without revealing user or device level data.

Good uses and abuse

Legitimate uses

  • Privacy-safe install measurement

Known abuse

  • Abused by conversion-value encoding to infer behavior

History

  • 2018-03, iPhone iOS 11.3: SKAdNetwork 1.0
  • 2019-06, iPhone iOS 13: Version 2: view-through attribution
  • 2021-04, iPhone iOS 14.5: Version 3 plus ATT, becomes the default measure for non-consented users
  • 2022-10, iPhone iOS 16.1: SKAN 4: multiple postbacks, hierarchical IDs, coarse values, web-to-app
  • 2024-03, iPhone iOS 17.4: AdAttributionKit introduced as the successor framework

Related capabilities

Related

  • SKAN conversion values (fine and coarse). Can send the ad network a small score about what you did after install
  • SKAN crowd anonymity tiers. Can't get much detail when too few people installed from an ad
  • SKAN postback windows and timers. Can only get install reports days later, in three windows with random delays
  • AdAttributionKit (iOS 17.4). Can tell an ad network an ad led to an install, on iPhone, with delays

Same idea on the web

  • Attribution Reporting API (retired). Can't measure which ad click led to a purchase in Chrome anymore

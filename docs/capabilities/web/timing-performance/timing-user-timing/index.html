User Timing marks and measures

Lets a page stamp named points in time and measure the gaps between them.

Works without askingSpeed and timingMeasurementWeb browsersWhile you use it

In one line

Can mark points in time and measure gaps between them inside the page

Lets a page stamp named points in time and measure the gaps between them.

A site can time its own code in detail and send the numbers home, so it learns how fast the person's device and network really are. The marks live only in this tab and are not shared across sites.

What it can and can't do

Reach 2 of 4While the page is open

What the user does: Nothing. It happens as the page runs

It can

  • Stamp named moments in its own code
  • Measure how long each part took
  • Send the timings home to the site
  • Learn how fast your device and network really are

It cannot

  • Share marks between tabs, since they live in this tab only
  • Ask permission first
  • See your files
  • Keep the marks after you close the tab

Typical flow

  1. Page calls performance.mark(name)
  2. Browser records a timestamp with sub millisecond precision (subject to coarsening)
  3. Page calls performance.measure(name, a, b)
  4. Page reads entries or sends them to a server

Data you get

Shape: none

No individual data fields. The signal is the access itself.

Technical limits

  • Entries are per document and are not shared across origins
  • Timer resolution is coarsened: Chrome uses 100 microseconds (5 microseconds on cross-origin isolated pages); Firefox rounds more coarsely by default
  • No hard entry limit in the spec; browsers hold them in memory until cleared
  • detail object lets a page attach arbitrary data to a mark
  • Entries do not survive navigation

The story

What it is

A page can mark named points in time and measure the gaps between them.

For you

You never see it. Teams use it to label steps like Search started and Results shown, then measure from real visitors. That is how they find what slows you down.

For makers

It is the standard way to time what matters to your product, such as time to first video frame or time to checkout. Teams send the results to dashboards to compare releases.

Risks

  • Reports sent to vendors
  • Rarely harmful on its own

What the platform says

  • MDN: User Timing. Lets developers add their own timing marks, so they can measure how long key steps take.

Good uses and abuse

Legitimate uses

  • Performance monitoring (RUM)
  • A/B and perf test harnesses
  • Profiling in DevTools Performance panel

Known abuse

  • Timing side channels
  • Device speed fingerprinting

In one line

Can recognise you across sites with embedded cookies, unless your browser blocks them

Whether an embedded site can set and read its own cookies on other sites, which varies by browser.

Third-party cookies are how ad networks recognise the same person across sites. Safari blocks them, Firefox partitions them, Brave blocks them, Chrome leaves them on by default (user choice) and blocks them in Incognito.

What it can and can't do

Reach 4 of 4Across many sites, unless blocked

What the user does: Nothing. It happens when a page with ads or embeds loads

It can

  • Set and later see its own cookie from inside a page on another site
  • Link your visits across the sites that embed it
  • Keep working in Chrome, where these cookies stay on by default
  • Ask the browser for access if it was blocked (Storage Access prompt)

It cannot

  • Set these cookies in Safari, which blocks them
  • Share one cookie across sites in Firefox, which keeps a separate jar per site
  • Use them in Incognito windows in Chrome
  • Get through in Brave, which blocks them

How it differs between platforms: Safari and Brave block them, Firefox splits them per site, and Chrome allows them by default but blocks them in Incognito.

Technical limits

  • Safari: blocked for all, no exceptions except Storage Access API
  • Firefox: Total Cookie Protection partitions per top-level site by default (June 2022, Firefox 103)
  • Chrome: kept on by default; no deprecation prompt after the April 2025 decision; Incognito blocks by default
  • Edge: Tracking Prevention blocks classified trackers, not all

The story

What it is

Whether an embedded site can store cookies on other sites, which depends on which browser you use.

For you

You never see these cookies, but they decide whether an ad for boots follows you from a shoe shop to a news site. In Safari and Firefox it mostly cannot. In Chrome it still can, unless you turn it off in settings.

For makers

Ad networks use these cookies to recognise the same person across sites for targeting, frequency caps and conversion counting. Sites also use them for legitimate embeds like logins and payments. When a browser blocks them, makers must switch to first-party data or new APIs.

Risks

  • Cross-site profiles of your habits
  • Settings differ by browser, so protection is uneven

What the platform says

  • Apple: Intelligent Tracking Prevention. Safari blocks cross-site tracking by default so websites cannot follow you from site to site.
  • Mozilla: Enhanced Tracking Protection. Firefox keeps each site's cookies in a separate jar so trackers cannot connect your visits.
  • Google: Privacy Sandbox. Chrome kept third-party cookies and gives people a choice, while offering newer ad tools as alternatives.

Good uses and abuse

Legitimate uses

  • Embedded video, chat, SSO, payment frames
  • Ad measurement

Known abuse

  • Cross-site profile building by ad networks
  • Silent identifiers synced across domains

History

  • 2020-03, Safari 13.1: Full third-party cookie blocking
  • 2022-06, Firefox 103: Total Cookie Protection default for all users
  • 2024-01, Chrome 120: 1% of Chrome users had third-party cookies restricted (testing)
  • 2024-07, Chrome 127: Google proposed user choice instead of deprecation
  • 2025-04, Chrome 135: Google confirmed no standalone prompt; users keep the Settings choice
  • 2025-10, Chrome 141: Oct 17: Google retired most remaining Privacy Sandbox APIs; third-party cookies stay

Related capabilities

Related

  • CHIPS partitioned cookies. Can keep a cookie for an embedded service, separate for each site it appears on
  • Storage Access API. Can ask to use its own cookies when embedded in another site
  • Cookie syncing. Can let ad companies swap IDs so each recognizes you across sites
